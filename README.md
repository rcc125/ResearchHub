# ResearchHub V0.3（基于你运行成功的 V0.1 升级）

这是用于**本地教学和虚拟受试者数据**的可运行原型，不可直接用于真实受试者招募或医疗健康信息采集。保留了原有用户、受试者、项目、参与关系和项目专属问卷表，新添项目研究人员权限、采集记录和预约记录。**不用删除你原来的 Docker 卷或 MySQL 数据库。**

## 先备份，再升级（Windows PowerShell）

1. 微信开发者工具中先保存改动并关闭项目，FastAPI 的 PowerShell 窗口按 `Ctrl+C` 停止。
2. 将已有 `E:\Projects\ResearchHub` 文件夹**整个复制一份**为 `ResearchHub_backup`。有数据时还应另做 MySQL 数据库备份。
3. 解压下载的 `ResearchHub_v0.2.zip`，把里面 `ResearchHub/backend/app/main.py`、`ResearchHub/backend/requirements.txt`、`ResearchHub/miniprogram` 下更新和新增的页面文件、`ResearchHub/sql/schema.sql` **合并覆盖**到你原来的项目。最简单的办法是解压后复制整个 `ResearchHub` 文件夹到 `E:\Projects\`，选择合并/替换同名文件；这次打包**不包含 `.env`**，不会覆盖已配置的数据库密码和 JWT 密钥。建议先备份。
4. 不要运行 `docker compose down -v`，它会删除数据库持久化卷。你之前启动的数据库可以继续使用。
5. 进入后端目录：

```powershell
cd E:\Projects\ResearchHub\backend
.\.venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt
python -m uvicorn app.main:app --host 127.0.0.1 --port 8000 --reload
```

本地运行时，新表由 SQLAlchemy 的 `create_all` 创建（**只创建不存在的表，不会删除旧表**）；`sql/schema.sql` 也包含可手动建表的 `CREATE TABLE IF NOT EXISTS` 语句，**不需要再对同一数据库重复导入**。生产系统应使用 Alembic 版本迁移，而不是依靠自动建表。

6. 打开 `http://127.0.0.1:8000/docs`，确认出现 V0.2 新接口；微信开发者工具重新编译 `E:\Projects\ResearchHub\miniprogram`。

## 在微信开发者工具中试用（重要：仅限虚拟测试数据）

1. `miniprogram/utils/config.js` 保持 `DEMO_MODE = true`、`BASE_URL = 'http://127.0.0.1:8000'`，后端 `.env` 设置 `DEMO_MODE=true`。
2. 「本地演示登录」→ 保存基础资料 → 科研项目 → 填写 CVP/PPG 项目专属问卷（这样系统建立参与关系）。
3. 在「科研项目」页点击「科研管理工作台」→「启用本地演示管理员（仅测试）」。此按钮需要**后端本机环回地址 + 演示模式 + 本地演示账号**，正式环境无法使用。
4. 在工作台选择项目、找到受试者，点击「登记采集结果」，把一次采集标记为「失败」并填写失败原因和实际采集时间。
5. 返回项目页，点击「我的采集记录 / 重约」→「申请重新预约」，选一个未来日期时间并提交。
6. 回到管理工作台，找到待处理预约，审核并填写未来确认时间。
7. 点击「导出当前项目 Excel」，得到含三张工作表的 XLSX（受试者基础信息、采集记录、预约记录；导出不包括微信 OpenID 等身份凭据）。

**演示模式所有本地登录共用一个假账号**，只能模拟操作流；它不能用来测试两位真实不同受试者之间的登录隔离，更不能上线公开访问。

## 常见错误

- `403 无此项目的科研管理权限`：未点击本地演示管理员开通按钮，或正式账号没有项目权限。
- 管理工作台没有受试者：请先保存基础信息，再提交此项目专属问卷，才能建立 `enrollments` 参与记录。
- `409 这次失败记录已有待处理或已确认预约`：重复预约拦截成功。
- `422 采集日期不合理`：必须填写实际已经发生的采集日期时间；确认预约时间必须在未来。
- 后端报 `ModuleNotFoundError: openpyxl`：运行 `python -m pip install -r requirements.txt`。
- 小程序网络请求失败：检查 Uvicorn 仍在运行、后端地址、开发者工具本地合法域名校验设置。手机真机不能直接使用电脑的 `127.0.0.1`。

## 当前功能与限制

- V0.1：微信身份后端、演示登录、基本资料、项目列表、项目自定义问卷。
- V0.2：项目级研究人员权限、采集记录、失败重约、受试者自行查看记录、预约审核、匿名编号 Excel 导出。
- 暂未完成：生产级管理员邀请/审核；真正的研究项目知情同意与伦理工作流；强制预约时间槽排他校验；并发写入序号的锁和重试机制；删除/撤回同意的完整处理；手机号加密和审计日志；生产 HTTPS/合法域名；分布式部署和 Alembic 迁移。

未经过权限审查、伦理审批和个人信息保护评估前，**禁止把真实受试者身份信息、健康信息或实验数据写入本演示平台**。


## V0.3 更新内容

- 基础资料增加姓名字段；旧数据库启动时自动新增可空字段，旧档案可编辑后补齐姓名。
- 项目展示负责人姓名；管理端可以设置负责人、工作日（ISO 周一=1 至周日=7）和每日预约时间范围。
- 保存项目专属问卷后可以预约首次采集；失败采集仍可申请重新预约。
- 增加“项目预览 / 个人中心”底部导航。
- PPG 采集部位扩展到左右手十个手指。
- 采集登记页会优先带入最近一次已确认预约的日期时间；可按实际采集情况调整。未来时间不能提前登记为已完成采集。
- Excel 中采集日期、采集时间拆分为独立列；受试者资料表增加姓名列。
- 近期采集与预约审核列表支持点击查看详情。

### 从 V0.2 升级

请先备份项目目录和数据库，再用 V0.3 文件覆盖代码（保留 `backend/.env`）。启动 FastAPI 时会自动执行本地原型的增量数据库升级，不会删除旧表或旧记录。若启动时报数据库迁移错误，请停止服务并保留报错，不要删除 Docker volume。正式使用前应采用 Alembic 迁移并关闭演示管理员功能。
